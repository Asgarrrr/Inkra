It opened its own temp workspace only `if (!open)` — that is, only when no workspace was already restored — so once another spec seeded `recent_workspaces.json`, it silently ran its assertions against that workspace instead and failed with "no palette row for big-images-tables.md", naming nothing about the real cause. `latex-math`, `section-rail-fisheye` and `table-column-sizing` all seed into whatever workspace startup restores; they are correct today only because that happens to be a repo with the files they want. - Characterize content search at scale — the one thing the feature shipped without. The scan is sequential and reads every file in the index, stopping early only on a cap (`total_cap` 500, `per_file_cap` 10, `max_bytes` 2 MiB), and the index is cloned per invocation (~186 B/entry measured at slice 2, so ~186 MB at a million files — never verified). Needs a synthetic vault generator (nested tree, realistic sizes, some frontmatter, ~1% pathological lines of base64 or minified JSON, planted tokens at known density), measured in **release** across 1k / 10k / 100k / 1M files, on four query shapes: rare token (worst case — full scan), frequent token (hits the cap early), two tokens, and literal. Report indexing time, index footprint, time-to-first-batch (the perceived latency) and time-to-completion. Worth keeping as a harness for the next time the scan changes. Background in `SPECs/fuzzy-search-grep-mr.md`.
- Build note kept from the `latex-math.spec.js` work — the e2e bundle only builds through `e2e/package.json`'s `build:app` (`--features e2e --bundles app` plus its `--config`); a bare `cargo tauri build` yields an app with no WebDriver plugin, which surfaces as a session-creation timeout rather than as a missing feature, and overwrites the good bundle on the way. A second trap: the `beforeBuildCommand` is `vp build`, so `vp` must be on `PATH` (`node_modules/.bin`) or the build fails at exit 127 and silently leaves the previous bundle in place, which then gets tested instead.

Worth a look on its own terms: that `setTimeout(0)` against mouseup is load-bearing for images, horizontal rules and math alike, and nothing but wall-clock luck separates it from refolding.
